## 0. 阅读说明

这份总结只覆盖 2026-07-01 至 2026-07-14 的本地证据。为了避免把设计文档、预检、崩溃运行和正式实验混为一谈，全文采用三种证据标签：

- **事实**：有 checkpoint、完整日志、正式评测或可重复测试支撑；
- **推断**：由多个事实共同支持，但仍需要新的因果实验确认；
- **建议**：面向下一阶段的执行判断，不冒充已经得到的实验结论。

所有 AP 数值使用 `0–1` 表示。口头所说的 “AP70” 对应 `0.70`。不同数据口径之间禁止直接横向比较。

## 1. 两周总判断

### 1.1 最重要的结论

1. **过去两周不是“训练没有任何用”，而是完成了从错误问题到可证伪问题的收敛。** 早期路线主要在问“query 多一点、训练久一点、top-k 换一下、teacher 换一下会不会好”；正式控制实验已经逐项排除了这些弱解释。后期问题被收敛为：如何在固定查询、无 NMS、无 dense inference head 的条件下，让 query 同时保留自身语义、吸收图像证据、承担连续实例容量，并在空图和长尾类别上正确校准。
2. **AP70 只在特定口径或多源策略上出现，尚未成为 strict raw-full-val 单模型结果。** filtered `6,605` paper-mouth 的强基线约为 `0.705`；G27C 非 oracle router 为 `0.706429`。G17/G19 的约 `0.7004` 来自多源 class/source policy，不是单 checkpoint、单 forward。raw all-patch `13,833` 的 dense scaffold 基线是 `0.660225`，strict no-head 旧线长期在 `0.40–0.43`。
3. **strict no-head 旧实现的低平台是结构性问题，不是单纯预算问题。** P111 GT pre-topk oracle `0.4186`、P131 q300 长训 `0.4142`、P134B full-train `0.4239`、P136 density calibration `0.4042`、P142 rotated dense-distinct constructor `0.3311`，共同说明仅改变候选选择、query 数、训练长度或浅层 loss 不能恢复 dense remote-sensing detection 所需的 objectness、local quality、旋转状态、重复竞争与空图校准。
4. **历史路线不能整体判死。** P149、P156、P167、P170、P175 留下了稳定训练、slot state、主路径 lifecycle、competitive memory 和严格输出预算的正证据。合理丢弃对象只能是已经完成匹配预算验证的精确拓扑，例如 query state 被覆盖、后置几何扰动、无所有权扩群、巨型多模块串联等。
5. **OpenSetFlow 找到了真实机制信号，但还没有追平父模型。** HRSC 单类上，R19 冻结 coupled adapter 可重复达到 `AP50=0.648`，R25 query-preserving fusion 达到 `0.650`；DOTA2 raw `13,833` 上，R25 1E 为 `0.3016`，E3 选择权重为 `0.3520`，R29 balanced E5 达到 `0.3698`。后者相对同口径控制 E5 提升 `+0.0205`，但仍低于冻结父模型 replay `0.4032`。
6. **长训失败的直接原因已被实验定位为 calibration drift。** R25 从 E3 延长到 E7，没有分支达到 `+0.010 mAP` 门槛；空图 foreground mass 上升，背景 query 的 evidence gate 高于 matched query，而且差距继续扩大。问题不是“epoch 还不够”，而是当前 reduction、gate 和 null 目标把容量分配给了错误 query。
7. **R29 balanced 是当前最值得继续验证的训练轴。** 它在 18 类中 14 类提升、3 类持平、仅 1 类轻微下降，同时恢复空图 mass 与 gate-gap 退化；但 evidence projection condition number 升至约 `6.05e4`，仍需多 seed、E7/E10 与条件数监控，不能直接无审计长训。
8. **OV-CapFlow 已完成代码级 strict substrate 与 semantic-capacity 原型，但尚无训练成绩。** 当前实现已有固定 learned query/reference、每 query 单类别输出、native/evidence 零门融合、identity/orthogonal adapter、连续 capacity 和 count/mass losses；17 个 focused tests 通过。尚缺真实数据 batch、DOTA2 18 类配置、显式 null reservoir 和正式训练。

### 1.2 当前阶段定位

当前不是“已经拿到论文主结果”，也不是“方向死亡”。更准确的定位是：

> 已经找到一个值得做论文级因果验证的候选骨架，并找到一个在 DOTA2 多类 raw-full-val 上显著正向的训练轴；下一步要把这些证据迁移到公开、可复现的 OV-CapFlow substrate，并用严格 gate 决定是否投入中长训。

## 4. 早期强基线与 AP70 口径

### 4.1 强 scaffold 结果

| Exp | Mouth | mAP | AP50 | Interpretation |
|---|---|---:|---:|---|
| TAC V00 FOCUS | full-val FOCUS mouth | 0.6962 | 0.6960 | 7 月 1 日强控制 |
| G2E-v2 b24 | same family mouth | 0.6966 | 0.6970 | `+0.0004 mAP`，真实但极小 |
| P83A4/P41C | raw13833 | 0.660225 | 0.6600 | raw all-patch baseline to beat |
| P77E/G20A | paper6605 | ≈0.7050 | ≈0.7050 | filtered paper-mouth baseline |
| G27C | paper6605 | 0.706429 | n/a | 最好非 oracle router，`+0.001407` |

这些结果告诉我们：现有 dense/OpenRSD scaffold 并不弱，真正困难的是在删除 dense inference machinery、NMS 和全局筛选之后，仍保持相近能力。

### 4.2 AP70 到底意味着什么

- G17 validation-tuned policy `mAP=0.700439`；
- G19 fixed attribute policy `mAP=0.700379`；
- 两者由多源 prediction pool 按 class/source policy 组合，不能写成单模型 AP70；
- G20F oracle `0.708806` 只表示 source pool 上限；
- G27C `0.706429` 是较干净的非 oracle router，但仍属于 filtered paper-mouth 推理策略。

因此，过去两周没有得到“strict E2E、raw13833、单 checkpoint、单 forward、无 NMS 的 AP70”。这一边界必须在后续论文叙事中保持。

## 5. strict no-head 旧线为何停在低平台

### 5.1 关键控制实验

| Exp | Change | raw13833 mAP | Result scope |
|---|---|---:|---|
| P26-B-only | layer consistency / strict control | 0.4310 | 旧线相对最稳控制 |
| P110A | semantic-angle query state competition | 0.4256 | 语义/角度组合未突破平台 |
| P111A | GT oracle pre-topk | 0.4186 | GT 选 query 仍低，top-k 不是主因 |
| P131A E20 | q300 + scale bank | 0.4142 | query budget 与延训不够 |
| P132A E10 | shallow O2M/distinct/cardinality | 0.4139 | loss patch 没进入 query state |
| P133A E10 | dense teacher pseudo positives | 0.4000 | 低阈值 pseudo 污染背景/empty |
| P134B E10 | full train 47,294, clean no-teacher | 0.4239 | 排除“只是 2,000-set 太小” |
| P135A E5/E10 | first dense scaffold implementation | 0.3938 / 0.3865 | 当前实现未形成有效 distinct/ranking state |
| P136A E5 | density-calibrated rotated set | 0.4042 | density score/loss patch 不足 |
| P142A E5 | rotated dense-distinct constructor | 0.3311 | 当前 pre-decoder constructor 显著负 |

P142A 的 `0.3311` 来自原始日志完整 raw13833 validation：small-vehicle 有 `1,677,226` detections、AP `0.183`；bridge 有 `1,078,537` detections、AP `0.220`；container-crane AP 为 `0.000`。模型随后进入 E6，再收到外部 SIGINT/SIGTERM。E5 结果本身完整有效；后续信号终止不使 E5 失效。

### 5.2 被排除的弱解释

| Hypothesis | Evidence | Verdict |
|---|---|---|
| 训练轮数不够 | P131 E20 低于 E10；P134 full-train 仍 0.4239 | 基本排除 |
| 数据子集太小 | P134 使用 47,294 full train 仍低平台 | 基本排除 |
| query 数太少 | q300/q600 未产生结构突破 | 单独增加无效 |
| top-k 选错 | P111 GT oracle 仅 0.4186 | 排除为主因 |
| teacher 不够强 | P133 teacher detections 反而降到 0.4000 | 当前 pseudo route 负 |
| 加 O2M / duplicate loss 就够 | P132/P135/P136 未突破 | 浅层 patch 不够 |
| pre-decoder dense-distinct 就够 | P142 0.3311 | 当前实现明确负 |

### 5.3 结构性根因

strict no-head 删除 dense scaffold 后，没有等价重建以下能力：

1. multi-scale dense positive supervision；
2. dense-to-distinct query birth；
3. query-level objectness 与 rotated localization quality；
4. 实例所有权和局部 winner competition；
5. empty-tile no-object / null calibration；
6. 长尾类别与场景密度对应的连续 capacity。

这不是说推理期必须恢复 dense head，而是训练与 decoder state 必须内生地学到这些能力。

## 7. OpenSetFlow 从 R1 到 R25 的结构演进

### 7.1 R1：shared transport 可以学，但读出与状态有问题

匹配 HRSC 10E 协议：fixed 600 queries、无 NMS、无 survivor top-k、无 dense inference head。

| Variant | AP50@5E | AP50@10E | Delta vs matched P149 |
|---|---:|---:|---:|
| P149 matched | 0.512 | 0.696 | 0 |
| P175 matched | 0.431 | 0.570 | -0.126 |
| OpenSetFlow shared | 0.168 | 0.500 | -0.196 |
| OpenSetFlow factorized | 0.277 | 0.493 | -0.203 |

shared 从 E5 到 E10 增长 `+0.332`，证明不能在 E5 草率判死；但 E10 明确低于 P149，说明当前版本未过 gate。早期 mask、DN 和 posterior normalization 崩溃均属于工程无效记录，修复后的完整运行才是科学证据。

### 7.2 R2/R3：主要瓶颈是 transport readout，不是框完全坏了

| Variant / Readout | AP50 | Meaning |
|---|---:|---|
| R2 shared + coupled | 0.4933 | 当前 transport score |
| same boxes + legacy score | 0.6032 | 框有更高可用上限 |
| same boxes + expected transport energy | max 0.5506 | transport cost 含真实排序信号 |

shared-coupled 在 E5 的 duplicate extras/GT 为 `0.6460`，factorized-coupled 为 `3.3271`；positive mass 为 `0.3608` vs `0.0479`。这支持 shared capacity 限制重复、改善正样本质量，但默认读出没有把机制收益充分转成 AP。

### 7.3 R4–R18：从不稳定全模型训练收敛到冻结 adapter

这批实验最重要的贡献不是单个最高分，而是找到可复现性根因：

- R4/R6 单次赢家会随初始化翻转，range 可达 `0.214`，禁止挑单次峰值；
- R9 optimizer isolation 缩小方差，但没有根治；
- R10 冻结 detector、只训练 transport adapter，三次 E5 均 `0.634`；
- R11 去 normalized-mass loss 后，E5 `0.648`，重复 checkpoint 逐张量一致；
- R12 gentle pose 提高 same-box legacy ceiling，但最终 transport score 未兑现；
- R14/R15/R16 证明 joint semantic+pose、gate-only pose 和 staged pairwise 的精确配方无益；
- R18 早层语义监督近中性，说明 deep supervision 不是 HRSC 当前瓶颈。

由此形成的原则是：先冻结强 detector/box trajectory，只训练小型、可观测、可逐位复现的 semantic-capacity adapter；机制成立后再考虑解冻。

### 7.4 R19–R24：共享路径、实例容量与 semantic overwrite

| Round | Structure | AP50 | Decision |
|---|---|---:|---|
| R19 | minimal null / semantic / coupled effective path | `0.635 / 0.645 / 0.648×2` | coupled canonical |
| R20 | absolute GWD soft-null | best `0.619` after fix | 存在性与定位质量冲突，停止精确配方 |
| R21/R22 | positive GWD pairwise / balanced scale | max `0.648` | 消除大回退但无增益 |
| R23 | ownership / score / scale diagnosis | ownership `0.8956`；dup/GT `1.9845`；small coverage `0.736` | 问题转为实例容量与局部 winner |
| R24 | evidence-only joint posterior | `0.642×2` | 完全替换 query semantics 明确负 |
| R24-density | joint + continuous density | `0.643×2` | `+0.001` 机制信号，未晋级 |

R24 的关键结论不是“density 死亡”，而是：

- evidence-only posterior replacement 丢失 query-specific discrimination；
- continuous density capacity 确实提高 positive mass、改善 existence Brier；
- 但 null calibration 同时恶化，净 AP 仍低于 R19；
- 下一结构必须保留 query 自身语义，再融合 transported evidence，并保留 continuous density 作为受控因素。

### 7.5 R25：保留 query 语义后，结构得到小而真实的增益

| Structure | mAP | AP50 | Recall | Reproducibility |
|---|---:|---:|---:|---|
| R19 | n/a | 0.6480 | n/a | deterministic adapter |
| R24 evidence-only | n/a | 0.6420 | 0.896 | two repeats |
| R24 evidence-only + density | n/a | 0.6430 | 0.896 | two repeats |
| R25 fusion, no density | 0.6498 | 0.6500 | 0.896 | 504 tensors, 0 diff |
| R25 fusion + density | 0.6497 | 0.6500 | 0.896 | 504 tensors, 0 diff |

R25 的 gate 没有退化成常数：no-density 全部 query gate 均值 `0.0971`，matched query `0.1642`，local winner `0.1802`。这说明结构学到“大部分 query 保留自身语义，目标 query 适当增加 evidence”。Canonical 选择 no-density，是因为 exact mAP 略高、结构更简单；density 保留为多类场景下的受控机制，不在 HRSC 单类继续扫强度。

## 8. 从 HRSC 转向 DOTA2.0：R19/R25/density matched 对照

### 8.1 R26 1E full transfer

固定协议：DOTA2.0 18 类、train `47,294`、raw val `13,833`、fixed `Q=200`、无 NMS、无 dense inference head、无 survivor top-k、冻结 P134B substrate。

| Variant | mAP | AP50 | Delta | Decision |
|---|---:|---:|---:|---|
| parent replay | 0.4032 | 0.4030 | n/a | frozen substrate reference |
| R19 | 0.0604 | 0.0600 | n/a | category allocation collapse |
| R25 rep1 | 0.3016 | 0.3020 | +0.2412 vs R19 | promote |
| R25-density | 0.2993 | 0.2990 | -0.0023 vs R25 | current density point reject |
| R25 rep2 | 0.3016 | 0.3020 | exact repeat | replica gate pass |

R19 的失败边界很明确：关闭 query-preserving fusion 后，多类类别分配塌缩。它不能外推为整个 transport family 死亡。R25 在 18 类上恢复了大量类别，但 airport、container-crane、helipad 仍为 0 或严重失衡。

### 8.2 执行层发现：固定 batch24 不安全

DOTA2 单图最多约 3,396 个实例；DINO DN self-attention 随 DN query 数平方增长。固定 batch24 在稠密区域 OOM，只否定执行方案。最终使用 `DNQueryBudgetBatchSampler`：47,294 张图全部覆盖一次，1,979 updates 中 1,959 个为 batch24，20 个稠密/边界 update 自动缩小，最小 batch5。

| Arm | Best after E3 | E7 | Best delta vs E3 |
|---|---:|---:|---:|
| default-s12 | E4 `0.3525` | 0.3481 | +0.0005 |

没有分支达到预注册 `+0.010` 门槛。按 `mAP 0.001` tie-band 和 calibration tie-break，选择 default E3 `0.3520`，而不是只高 `0.0005` 但 empty mass 更差的 E4。

### 9.3 长训为何无用

default 的 empty-tile foreground mass 从 E3 `0.944756` 升到 E7 `1.071879`；matched/unmatched gate 从 `0.681050/0.752004` 变成 `0.719548/0.823140`。背景 query 的 evidence 权重始终更高，且差距从约 `0.0710` 扩大到 `0.1036`。

Airport recall 从 E3 到 E7 始终为 `0.702970`，但约 `91.7%` query prediction 被分到 airport。延训没有增加 airport 覆盖，只增加背景前景质量和校准误差。

因此合理结论是：停止“当前固定 LR `5e-5`、当前 reduction/gate/null 目标”的机械延训。Identity 更耐久、Orthogonal 条件数更好，但二者都不是 calibration 解法。

## 10. R29 calibration causal validation

### 10.1 Stage A：power replay

V1 因 checkpoint load 把配置 power 8/16 覆盖回 32，实际没有干预，只能算无效实验。V2 修复后：power 8 将 E3→E7 empty-mass 退化相对 power 32 减少 `35.98%`，mAP 变化从 `-0.0039` 反转为 `+0.0004`。

但当前实现先 `exp` 再 `argmax`，power 32 导致大量 class score 下溢为 0，平票偏向 class 0/airport。Power 8 改变了标签，而 class-common scaling 理论上不该改变 argmax。结论是“高 power 与漂移有关”有支持，但受到 underflow 混杂；必须先改 log-space stable selection，再重放。

### 10.2 Stage B：四个单变量因果对照

| Arm | E5 mAP/AP50 | Delta vs control E5 | Mechanism result | Decision |
|---|---:|---:|---|---|
| historical control | 0.3493/0.3490 | 0 | calibration degrades | control |
| balanced reduction | **0.3698/0.3700** | **+0.0205** | empty recovery `37.9%`；gate-gap recovery `542.4%` | promote |
| query_aux 0.5 | 0.2236/0.2240 | -0.1257 | query Brier 大幅改善但检测排序被破坏 | stop exact weight |
| gate_frozen | 0.3554/0.3550 | +0.0061 | gate drift 有因果作用 | retain counterfactual |
| lr_decay `1e-5` | 0.3536/0.3540 | +0.0043 | 减少总体投影/空图漂移 | retain counterfactual |

Balanced 相对控制在 18 类中 14 类提升、3 类持平，仅 harbor `-0.002`。这比单类 HRSC 的微小 `+0.002` 更有说服力，因为它同时满足多类 AP 和预注册 mediator gate。

### 10.3 仍未解决的风险

- balanced E5 仍低于 parent replay `0.4032`，差 `0.0334`；
- airport prediction share 仍约 `90.66%`；
- container-crane 与 helipad AP 仍为 0；
- evidence projection condition number 升到约 `60,532`；
- 当前只有一个 seed、E5 终点，不能证明中长训稳定。

因此 balanced 是“最有潜力投入下一轮验证”，不是“已经可投 40E”。

## 11. 对失败原因的统一解释

### 11.1 Query 语义被覆盖

P154、R24 和多类 R19 都指向同一规律：直接用 dense/evidence state 覆盖 query state，会丢失 query-specific discrimination。正确注入形式应是 identity-preserving、zero-gated residual，而不是 replacement。

### 11.2 容量监督被 unmatched query 数量支配

固定 Q=200 时，绝大多数 query 未匹配。若按 query-average reduction，背景数量会主导 gate/null/mass 梯度。R29 balanced 同时改善 AP、empty mass 与 gate gap，是目前对该因果链最强的证据。

### 11.3 Empty tile 与 null calibration 不是次要问题

raw13833 包含空 GT tile。P71 empty oracle 曾把 dense scaffold raw mAP 推高约 `+0.0449`，说明 empty FP 是主要损失源。R25 E7 的 empty mass 持续恶化进一步证明，不能只报告 non-empty paper-mouth。

### 11.4 类别分配与数值稳定耦合

Airport 过度预测并非完全来自 recall，而与 score underflow、null power 和 class tie 行为有关。任何 temperature/power 实验都必须同时记录 effective value、log-space label invariance 和 airport share。

### 11.5 Long-tail 需要显式 class/query capacity

Balanced 能改善已有可检测类，却仍无法把 container-crane/helipad 从 0 拉起。说明 background balance 是必要条件，但不是 rare-class/open-vocabulary capacity 的充分条件。

### 11.6 HRSC 只能测几何与所有权

HRSC 是单类 ship 数据。R19/R25 在 HRSC 的可重复增益证明结构可优化、语义保留有益，但不能证明 arbitrary vocabulary、novel-class transfer 或 absent prompt calibration。

## 15. 两周工作形成的可复用原则

1. **先固定 mouth，再看 AP。** raw13833 与 paper6605 永远分开报告。
2. **先复现父模型，再训练 adapter。** 没有 parent replay，不允许解释 delta。
3. **小数据只作结构 gate。** HRSC 不作开放词汇结论，DOTA1000 不作 full promotion。
4. **状态注入必须保留 identity path。** replacement 是高风险默认项。
5. **所有 query 必须可审计。** 不用全局 top-k/NMS 掩盖容量与校准失败。
6. **AP 与 mediator 同时过门。** 只改善 Brier、condition number 或 duplicate，不等于检测改进。
7. **无效实验单独归档。** 配置被 checkpoint 覆盖、loss 未路由、NaN 前终止都不能当科学负结果。
8. **只丢弃精确配方。** 写明 commit、config、seed、mouth、checkpoint、症状和复活条件。
9. **单次峰值不能晋级。** frozen adapter 的逐位重复和多 seed 优先于 validation winner。
10. **中长训必须有早停与 calibration guard。** 训练 loss 正常不代表 query capacity 分配正确。

## 17. 最终阶段结论

这两周最有价值的成果不是某一个最高 AP，而是建立了三层可靠认识：

1. **任务层**：raw dense remote-sensing strict set prediction 的核心难点是 empty/null、dense ownership、local quality 和 long-tail capacity，不能被 filtered AP 掩盖；
2. **结构层**：query 自身语义必须保留，transported evidence 只能作受控 residual，continuous density 必须与 null calibration 共同设计；
3. **训练层**：unmatched 数量支配会造成 calibration drift，balanced reduction 已给出第一个 DOTA2 多类、机制和 AP 同向的显著正证据。

下一阶段不应回到“再堆一个模块”或“直接跑 40E”。应先在公开 OV-CapFlow substrate 上完成真实 batch、parent replay、balanced/null 因果矩阵，再决定是否投入多 seed 与中长训。具体执行边界见同目录的 `fplan_ov_capflow_next_stage_zh.md`。
